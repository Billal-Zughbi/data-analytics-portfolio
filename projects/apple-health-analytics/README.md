# Apple Health Analytics

A Python pipeline and Power BI model that turn an Apple Health `export.xml` into validated daily
metrics across activity, cardio, mobility and environment, with every aggregation rule written down and
tested.

Case study: [`/projects/apple-health-analytics`](../../website/src/app/projects/apple-health-analytics/page.tsx) on the portfolio site.

> **Privacy.** The original export, its extracted CSVs, the original `.pbix` and its screenshots contain
> personal health records and are never committed. Everything public (the site's charts, the sample tables)
> comes from a **synthetic** export generated by [`synthetic.py`](src/apple_health/synthetic.py).

## Question

How do you turn one large, multi-device XML export into daily numbers you can trust in a dashboard?
That means deciding what a day is, which device counts when two record the same walk, and how each metric
rolls up, since steps add but heart rate does not.

## Pipeline

```
export.xml ─► extract ─► normalize units ─► drop duplicates ─► flag out-of-range ─► de-duplicate devices ─► daily rules ─► quality report
 (private)    stream,      km/h→mph,        exact repeats      excluded + counted     watch > phone per        sum / mean /       + Power BI star schema
              local time   cm→in, kJ→kcal                                             metric-hour (additive)   energy mean /      + website JSON
              device class                                                                                     last / stood hours   (synthetic only)
```

| Module | Responsibility |
|---|---|
| [`metrics.py`](src/apple_health/metrics.py) | Registry: record type → metric key, canonical unit, **daily aggregation rule**, plausible range |
| [`extract.py`](src/apple_health/extract.py) | Streaming `iterparse`; local wall-clock time; device names replaced by `watch`/`phone`/`other` |
| [`transform.py`](src/apple_health/transform.py) | Unit conversion, duplicate removal, range flags, device de-duplication, daily fact table |
| [`quality.py`](src/apple_health/quality.py) | Data-quality profile: duplicates, units, ranges, overlaps, coverage |
| [`synthetic.py`](src/apple_health/synthetic.py) | Deterministic synthetic export, including realistic data problems |
| [`export_web.py`](src/apple_health/export_web.py) | Website JSON + Power BI CSVs; refuses non-synthetic input |
| [`legacy/`](legacy/) | The original March 2025 scripts, unchanged, for comparison |

### Daily rules

| Rule | Metrics | Why |
|---|---|---|
| `sum` | steps, distance, active energy, exercise minutes, flights | Additive; overlapping devices de-duplicated first |
| `mean` | heart rate, resting / walking HR, HRV, walking speed, step length, physical effort | Readings and rates are never summed |
| `energy_mean` | environmental and headphone audio (dB) | Decibels are logarithmic: `10·log10(Σw·10^(L/10)/Σw)` |
| `last` | VO2 max | Sparse estimate revised by the device |
| `stood_hours` | stand hours | Count distinct hours marked `Stood` |

Exercise minutes, flights and stand hours are zero-filled on days the watch was worn (it recorded heart rate)
and left blank on days it was not, so averages are not biased toward active days.

Grain of the main outputs: `daily_metrics_synthetic.csv` is one row per day; `fact_daily_metric.csv` is one
row per day × metric.

## Run it

```bash
cd projects/apple-health-analytics
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt

python -m pytest                                        # 21 rule and contract tests
PYTHONPATH=src python -m apple_health demo              # synthetic export → outputs below
```

`demo` writes (all synthetic, all small):

| Output | Purpose |
|---|---|
| `data/synthetic/export.xml` | Generated export (git-ignored; ~20 MB, regenerate any time) |
| `data/sample/daily_metrics_synthetic.csv` | Wide daily table |
| `data/sample/fact_daily_metric.csv`, `dim_metric.csv`, `dim_date.csv` | Power BI star schema |
| `outputs/data_quality_synthetic.json` | Full quality profile |
| `../../website/src/data/generated/apple-health/*.json` | Data behind the case-study charts |

### With your own export (stays on your machine)

```bash
# Unzip the Health app export into data/raw/ (git-ignored)
PYTHONPATH=src python -m apple_health profile --xml data/raw/apple_health_export/export.xml
```

`profile` prints counts only and writes nothing to the repository. The website exporter refuses to run on
non-synthetic data unless the code is changed deliberately.

## Data quality (synthetic run)

Full profile: [`outputs/data_quality_synthetic.json`](outputs/data_quality_synthetic.json). The generator plants
known problems so each check has something to find: a duplicated day (exact duplicates), watch + phone
overlap (device de-duplication), three weeks of walking speed in km/h (unit conversion), and heart-rate
glitches above 230 bpm (range flags).

## Limitations

* Personal tracking, not clinical measurement. Nothing here supports a medical conclusion.
* Device de-duplication works per metric-hour; Health's own merge is finer-grained.
* Days use local wall-clock time; travel across time zones can shift edge records by a day.
* The synthetic profile and its trends are invented to exercise the charts.
* The original report was reviewed from its layout metadata only; see `powerbi/README.md`.
